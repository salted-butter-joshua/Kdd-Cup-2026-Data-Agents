## 4. 写配置

本地配置文件：`configs/react_baseline.yaml`（已被 gitignore，不要提交密钥）。

结构如下，把模型名、接口、密钥换成自己的 OpenAI 兼容服务：

```yaml
dataset:
  root_path: data/public/input

agent:
  provider: deepseek          # deepseek | minimax | zhipu | openai | local
  model: 你的模型名
  api_base: https://你的接口/v1   # 可省略：按 provider 填默认
  api_key: 你的密钥
  max_steps: 16
  temperature: 0.0
  strip_think: true           # 过滤 <think> 等思维链，避免污染 ReAct JSON
  reasoning_split:            # null=按 provider；minimax 默认 true

run:
  output_dir: artifacts/runs
  run_id:                 # 建议留空，自动用时间戳；写死且目录已存在会报错
  max_workers: 4
  task_timeout_seconds: 600

eval:
  enabled: true           # false 则跑完不打分
  lambda_extra: 0.1       # 赛事多余列惩罚系数
```

`dataset.gold_path` 可省略：`root_path` 以 `input` 结尾时，自动用同级的 `output`。

### 切换 DeepSeek / MiniMax / 智谱 / 本地 OpenAI 兼容

用 `agent.provider` 选择：

| provider | 默认 `api_base` | think 处理 |
| --- | --- | --- |
| `deepseek` | `https://api.deepseek.com/v1` | 去掉文本里的 `<think>` 等标签 |
| `minimax` | `https://api.minimax.io/v1` | 请求带 `reasoning_split=true`，思维进 `reasoning_*` 字段；`content` 再剥一层标签 |
| `zhipu` | `https://open.bigmodel.cn/api/paas/v4` | 默认 `thinking.type=disabled`；`reasoning_split: true` 时开启思维，内容在 `reasoning_content` |
| `openai` | `https://api.openai.com/v1` | 通用 OpenAI SDK；本地地址可把 `api_base` 改成你的 `/v1` |
| `local` | `http://localhost:8090/v1` | 走同一套 `openai` 包；无密钥也可；仍会剥 `content` 里的 `<think>` |

`qwen` / `vllm` / `sglang` / `ollama` 会当成 `local`。

国内 MiniMax 可把 `api_base` 改成 `https://api.minimaxi.com/v1`。  
不填 `api_base` 时按 `provider` 自动填默认值。

本地 Qwen / vLLM 示例（对应 `POST http://localhost:8090/v1/chat/completions`）：

```yaml
agent:
  provider: local
  model: Qwen3.6-35B-A3B-FP8
  api_base: http://localhost:8090/v1
  api_key:            # 可空
```

`api_base` 填到 `/v1` 即可，不要带 `/chat/completions`（写上了也会自动剥掉）。SDK 的 `base_url` 就是这个根地址。

智谱 GLM-4.6V-Flash 的接口模型名是 `glm-4.6v-flash`（控制台显示名 GLM-4.6V-Flash）。

注意：

- 相对路径相对 `PHASE_1/` 解析，不是仓库根目录。
- `run_id` 只能是单层目录名，不能带 `\` 或 `/`。
- 同一 `run_id` 跑第二次会失败（目录已存在）。要复跑请换名字，或把 `run_id` 留空。

## 5. 常用命令

都在 `PHASE_1` 下执行。

看数据和配置是否可见：

```powershell
uv run dabench status --config configs/react_baseline.yaml
```

应看到 `dataset_root` 为 present，并打印任务数量。

看某一题的题目和 `context/` 文件：

```powershell
uv run dabench inspect-task task_11 --config configs/react_baseline.yaml
```

跑单题（推荐先这样验证接口）：

```powershell
uv run dabench run-task task_11 --config configs/react_baseline.yaml
```

先跑 2 道：

```powershell
uv run dabench run-benchmark --config configs/react_baseline.yaml --limit 2
```

跑公开集全部：

```powershell
uv run dabench run-benchmark --config configs/react_baseline.yaml
```

| 命令 | 作用 |
| --- | --- |
| `status` | 路径、配置、数据集是否存在、任务数 |
| `inspect-task <id>` | 题目、难度、context 文件列表 |
| `run-task <id>` | 跑一题，写出 prediction，并对照 gold 打分 |
| `run-benchmark` | 批量跑；`--limit N` 限制题数；跑完后打分 |
| `score <run目录>` | 对已有一轮结果按官方规则重新打分 |

## 6. 结果在哪

```text
PHASE_1/artifacts/runs/<run_id>/<task_id>/
├── trace.json          # 每步 thought / 工具 / 观察
├── prediction.csv      # Agent 交的答案表
└── score.json          # 该题官方规则得分

PHASE_1/artifacts/runs/<run_id>/
├── summary.json            # 跑通情况（交没交表，不是对错）
├── scores.csv              # 每题 score / recall
└── scores_summary.json     # mean_score（本轮平均分）
```

`run-task` / `run-benchmark` 跑完后会自动对照 `data/public/output/<task_id>/gold.csv` 打分，规则与赛事 Leaderboard 一致：

- 按列内容签名匹配（忽略列名、行序）
- `Score = max(0, 召回 − 0.1 × 多余列 / 预测列数)`
- 缺 `prediction.csv` 记 0 分，仍计入平均

只对已有 gold 的公开 demo 能打分。隐藏测试集没有 `output/`，本地算不出官方榜分数。

已有一轮结果、只想重新打分：

```powershell
uv run dabench score artifacts/runs/<run_id> --config configs/react_baseline.yaml
```

`task_11` 改提示词后的一次成功跑：8 步交卷，`prediction.csv` 与 gold 三行一致（`163109 / 2803470 / 4395720`，均为 `F, SLE`），官方规则下应为 1.0。细节见 `复盘.md`。

## 7. Agent 会用哪些工具

每题开工时把该题 `context/` 下的 CSV / JSON / SQLite（含官方 `context/db/*.db`），以及 `doc/*.md` 等叙述文档抽成的表，**入仓到本题独立的内存 DuckDB**（与冠军一致，不落盘、不和其他题共用）。`knowledge.md` 整份注入任务 prompt，不是表，也没有单独读取工具。对 lowest/highest/average 类题，交卷前须探查过 **细粒度（行级 MIN/MAX/AVG）与粗粒度（SUM/GROUP BY）** 两种聚合路径，否则 `answer` 会被拒。文件访问不出本题 `context/`。

| 工具 | 作用 |
| --- | --- |
| `list_tables` | 列出本题仓库里的表、列、类型、行数 |
| `run_sql` | 只读 SQL；探查带 LIMIT；`final=true` 全表结果留给交卷 |
| `answer` | 提交最近一次 `final=true` 的 SQL 结果并结束本题 |

单题最多 `max_steps` 步（默认 16）。连表必须等值 JOIN；只 SELECT 题目要的列；并列用 `WHERE col = (SELECT MIN(col) ...)`，不要 `ORDER BY LIMIT 1`。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 命令找不到、或提示不在项目里 | 先 `cd` 到 `PHASE_1` |
| `status` 里 dataset_root 为 missing | 数据没放到 `data/public/input/` |
| 接口报 401 / 连不上 | 检查 `configs/react_baseline.yaml` 的 `api_base`、`api_key`、`model` |
| `FileExistsError` / run_id 已存在 | 清空 `run.run_id`，或换一个新名字 |
| 有 `trace.json` 没有 `prediction.csv` | 步数用尽没调用 `answer`，打开 trace 看最后几步在干什么 |
| 报 `Invalid value for run.run_id` 且提到 `gbk` / `illegal multibyte` | 旧 bug：答案含中文时用系统默认 GBK 写 CSV。已改为 utf-8；重新跑即可。`run_id` 本身通常没问题 |
| 结果和 gold 行数差很多 | 先看是不是把对不上的 ID 也硬配进去了，见 `复盘.md` 第 2 节 |
